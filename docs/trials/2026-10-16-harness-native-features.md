# Native multi-agent, instructions, review and scheduling in Claude Code, Codex CLI and agy

Research date: 2026-10-16. Read-only research; nothing in the repository was changed.

## How to read this

- Every claim carries a URL. "unconfirmed" means I could not find it in a primary source. Facts I checked against something other than a fetched web page are tagged `[local]` (CLI help or output on this Mac) or `[gh]` (GitHub API release notes).
- Docs pages were read through WebFetch, which summarises. Where a wrong word would change the advice I cross-checked with `[local]` or `[gh]`.
- Versions on this Mac: Claude Code 2.1.287 (the docs describe features up to about v2.1.299, so a few need an upgrade), Codex CLI 0.162.0 (0.163.0 was released 2026-10-15), agy 1.3.5 `[local]`.
- OpenAI's Codex docs moved. `developers.openai.com/codex/*` now answers 308 and redirects to `learn.chatgpt.com/docs/*`. I cite the `learn.chatgpt.com` URLs. The redirect target was server-supplied, so treat that host as "believed OpenAI" rather than verified.
- Claude Code docs base: `https://code.claude.com/docs/en/`. Antigravity docs base: `https://antigravity.google/docs/`. Codex docs base: `https://learn.chatgpt.com/docs/`.

## What a rules file can rely on in all three

Safe to ask for (documented in all three):

1. Project rules in `AGENTS.md`, root plus nested directories. Codex and agy read it natively. Claude Code reads it natively only when no `CLAUDE.md` sits in or above the working directory, and needs v2.1.277 or later, so keep a one-line `CLAUDE.md` containing `@AGENTS.md` (this repo already does that). Budgets: Codex caps the combined chain at 32 KiB by default; agy truncates a rule file at 24,000 bytes and budgets 20,000 tokens for global and `always_on` rules.
2. A lead that spawns several same-vendor subagents in parallel, waits for all of them, and returns one summary. State how to divide the work, that the lead must wait, and what the summary contains. Codex's docs recommend exactly those three points; Claude Code and agy accept the same plain-language request.
3. A reviewer that is a separate subagent with its own context, plus a blocking check the rule cannot talk its way around: a `PreToolUse` hook that denies. All three have one (exit 2 or JSON deny in Claude Code and Codex, JSON `deny` in agy). Formats and file locations differ, so devctl would have to generate three configs.
4. Skills in the shared `SKILL.md` format. Codex and agy read `.agents/skills/`; Claude Code reads `.claude/skills/` and the docs do not list `.agents/skills/`, so keep the source in `.agents/skills/` and give Claude Code `.claude/skills/` (symlink or copy), as this repo's `.agents/` and `.claude/` guides already do.
5. Non-interactive entry points for a worker or reviewer started from another vendor's shell: `claude -p`, `codex exec` / `codex review`, `agy -p`. All three print the final answer on stdout and have a structured-output option (`--output-format json` plus `--json-schema` in Claude Code and agy, `--output-schema` in Codex).

Not safe to assume; the rules file must name a fallback or stay silent:

6. Naming a model: only the same vendor's models, and the value syntax differs. Claude Code takes an alias or full ID per invocation. Codex takes any model in the parent's provider per spawn or in `.codex/agents/*.toml`. agy subagents take only `inherit`/`flash`/`pro`; only the whole agy session takes a model slug. Nothing lets one lead spawn a native subagent on another vendor's model (except agy serving Claude or GPT-OSS models from Google's catalog for the whole session). "Spawn workers on provider X" therefore means "run X's own CLI through the shell", which no Harness documents as a native feature, and which has one official plugin (Codex inside Claude Code).
7. Subagents inheriting the rules. Only Claude Code documents inheritance of CLAUDE.md (and `AGENTS.md` through the import), hooks and permissions. For Codex only sandbox and approvals are documented; for agy only permissions, command prefixes, sandbox and `accept-edits`. The spawn prompt must restate the constraints that matter (branch, file ownership, forbidden actions, what to report).
8. Per-subagent worktree isolation: Claude Code yes (`isolation: worktree`), agy `branch` mode yes (mechanism unconfirmed), Codex unconfirmed for subagents (it has `codex --worktree` for a whole session). Safer: the lead gives each worker its own branch and path, or assigns disjoint files, and a worktree isolates files only, not credentials, ports or processes.
9. A native review command: Claude Code `/code-review`, Codex `/review` and `codex review`; agy has none. The review model can be chosen in Codex (`review_model`) and by defining a reviewer subagent in Claude Code.
10. Anything experimental or interactive-only: Claude agent teams (flag, interactive only), Claude dynamic workflows (typed `ultracode`/"use a workflow", not `-p`, not scheduled prompts), agent view (research preview), routines (research preview), `/code-review ultra` (paid, claude.ai login), agy `/boost` and `/teamwork-preview` (paid), `codex app-server` (experimental), `codex mcp-server` (removed in 0.154.0).
11. Unattended runs: each Harness soft-denies or fails actions that need approval, so a scheduled or headless run needs pre-allowed rules, a stricter sandbox and `--sandbox`/permission settings chosen up front (Claude `--permission-prompts none` with allow rules; Codex `--sandbox workspace-write`; agy `permissions.allow`).

Open questions I could not close (all marked unconfirmed above): whether Codex and agy subagents receive the AGENTS.md chain; whether Codex and agy `PreToolUse` hooks fire inside subagents; whether Codex can put a subagent in a worktree; how agy sets the `branch` workspace for a subagent; whether agy reads `CLAUDE.md`; Codex nesting-depth default; Anthropic's current billing treatment of subscription `claude -p`; Google's terms for scripted `agy -p` use.
