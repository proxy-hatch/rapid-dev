# Kit commands

The code behind `rapid-ship init`, `status` and `sync`. [cli.py](../cli.py) parses arguments and prints each result. Each module here returns its result; only `pull_request.py` also writes to stdout, to report push and pull request progress. The files these commands write are in [templates](../templates/AGENTS.md).

- [templates.py](templates.py) reads the manifest (`kit.toml`) and renders the template tree for one stack and project. It also reads the project's `[kit]` lists (`optional` and `exclude`) and holds `KitError` and `KitRefusal`. Discovery skips `.venv`, `__pycache__`, `.DS_Store` and `.pyc` files and, when the template root's `kit.toml` is tracked by git, every path git does not keep. A source run then renders what the wheel ships.
- [lock.py](lock.py) reads and writes `.rapid-ship/kit.lock`: a content hash for each managed file, a link target for each managed symlink and the template hash for each seeded file. It refuses a path that is not in its canonical form, such as `./devctl`.
- [init.py](init.py) vendors the Kit with create-only, all-or-nothing writes and commits it. It needs a clean work tree, and lists up to 20 changed paths when it refuses. It plans every write first and writes nothing when any managed file exists. It skips an existing seeded file, even one that is itself a symlink, and lists it for `rs-setup`. After the plan and before any write, it collects the checks the repository already has ([existing_checks.py](existing_checks.py)) into the result; a conflict leaves them empty. It then creates the branch `rapid-ship/init` at HEAD, writes, and commits exactly the created files and the lock; in a repository with no commits it commits on the current branch. A failed switch, write, add or commit removes what it created, switches back and deletes the branch. `resolve_variables` validates the template variables. The project name defaults to the GitHub repository name (`--repository`, else the `origin` URL), then to the main checkout's directory name. It never prints a remote URL.
- [existing_checks.py](existing_checks.py) finds the tool settings, hooks and workflows already in the repository, read-only and without running project code or a hook: Ruff, mypy, pytest, flake8, pylint, isort and Black settings (`pyproject.toml`, `setup.cfg` and `tox.ini` count only with a tool table or section), `.pre-commit-config.yaml`, `.husky/`, lefthook files, a configured `core.hooksPath` (`/dev/null` is no hooks), the executable non-`.sample` files in git's hooks directory, and `.yml` or `.yaml` files in `.github/workflows/`. A file it cannot read is listed as `<path> (unreadable)`, and init still succeeds. The CLI prints the sorted list after the commit line and before `Next:`, and prints nothing when the list is empty.
- [status.py](status.py) classifies each locked file against the work tree and the installed templates. It is read-only.
- [sync.py](sync.py) replaces unchanged managed files with their new templates and skips `[kit] exclude` paths. A managed file the project edited or deleted becomes the project's own: sync never changes it and records its entry as seeded with the current template's hash. `--revert <path>` writes the template back and records the entry as managed. Outside `--in-place` it commits on `rapid-ship/kit-sync-<version>`, then pushes and opens the PR through `pull_request.py`. After a failed write it restores the work tree: each file it changed, what it created and the starting branch.
- [pull_request.py](pull_request.py) writes sync's pull request body, and pushes the branch and opens the pull request with `gh`. `REVERT`, the command that gives a file back to the Kit, appears in the body and in the CLI's output.
- [writes.py](writes.py) writes and deletes Kit files for `sync`. `Undo` records each change, so a failed `init` or `sync` can put the work tree back.
- [git.py](git.py) makes the git calls: `git()` runs no hook (`core.hooksPath=/dev/null`, so neither command runs project code) and passes `--literal-pathspecs` (`literal=False` only for `check-ignore`, which refuses it), `work_tree_root` finds the top of the work tree, and `changed_paths` and `is_clean` read the status. `commit_paths` and `leave_branch` are the commit and the way back that `init` and `sync` share. `hooks_setup` is the one call that runs without the override, because the override hides the repository's `core.hooksPath`; it only reads, for `existing_checks.py`.

`KitError` means the command could not run, and the CLI exits 2. So does an `OSError` or `UnicodeDecodeError`, such as an unreadable managed file. `KitRefusal` means the repository's state refuses the request, and the CLI exits 1. Every write stays inside the repository and never passes through a symlink; use `safe_path` and `create_file` from [files.py](../files.py).

rapid_ship must not import devctl, so it has no shared process runner. Run git through `git()`. It and `hooks_setup` start git in `git.py`'s `_run`, the one git process call, which carries EX-4. The one other process call, `gh` in `pull_request.py`, carries an `rs-exception` for Ruff's S603.

Tests are `tests/test_kit_*.py`; see the [test guide](../../tests/AGENTS.md). They are offline: sync's push and PR use a fake there, a local bare repository and a stand-in `gh`, so no test contacts GitHub. Run `uv run pytest tests/test_kit_*.py` after a change here.
